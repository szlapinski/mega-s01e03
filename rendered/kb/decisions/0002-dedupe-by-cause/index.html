Parser: shared parsing ignores the tenant’s date order

For day-first tenants, the shared parser treats a day-first input as month-first. For example, Harbour Dental’s app report R-41200 describes 7 April becoming 4 July. R-41205 belongs here despite an intake tag of hint: Morrow Tax runs booking-v2, and the report came through the app. Fix parsing at the shared boundary using tenant locale or an unambiguous date representation. Check app, email and booking-v2 form inputs; test ambiguous dates and dates whose day exceeds twelve.

Hint: booking-v3 tells day-first tenants to enter month first

The booking-v3 form prints MM/DD/YYYY, but interprets what people type in tenant order. The misleading hint is a separate problem from the shared parser. R-41230 is a Copper Studio form report and belongs here despite being tagged parser. The affected configuration is a day-first tenant using booking-v3 through the form: Alder Physio, Copper Studio and Pale Harbour. Make the displayed hint agree with the form’s interpretation; test both together for each locale. Changing the shared parser alone does not fix this path.

Decision: one ticket per verified failure path

  1. Deduplicate export rows by report ID before counting.
  2. Read the body and look up the tenant. Establish tenant locale, form version and input channel.
  3. Merge only when those facts support the same cause. Subject text and browser-locale intake tags do not establish cause. Different subjects can still describe the same cause.
  4. Keep parser and hint reports in separate tickets. Give each ticket its report count and evidence.
  5. If a tenant is missing, the cause is unknown, or the body contradicts the classification, keep the report separate for investigation. Do not merge merely because the subject matches.

What the timeline changes

Received time and merged time are different events. Reports arrived from April onward; the July merge batch measures desk processing, not the beginning of customer impact. The queue continues after that batch. A known label and a queued parser fix do not show that all reports are covered, that the hint has an owner, or that either fix has shipped.
